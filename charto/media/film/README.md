# charto-demo-30s — the UI-rendered demo film

`renders/charto-demo-30s.mp4` · 1920×1080 · 30 fps · 30.0s · H.264 + AAC ·
**−14.3 LUFS** (web-normalised) · poster at `renders/charto-demo-poster.jpg`.

Every frame is the **real product**. The four stills in `assets/` are Playwright
captures of Charto running against the live dataserver on `:5174` with 1,062,818
RELIANCE 1-minute bars — real questions, real tool calls, real answers. Nothing
in the film is a mockup, and no number on screen was typed by hand. Which is the
point: the claim the film makes is *"nothing is drawn that wasn't computed"*, so
the film could not itself be staged.

Beat 4 is the one to watch: the panel visibly says *"there is no clear
stock-specific catalyst"* and *"I cannot attribute the move to the index without
guessing."* A demo that shows the product declining to answer is a stronger
trust signal than one that shows it always answering — and it is the honest
half of the constitution, on camera.

## How it was made

Voice is ElevenLabs `eleven_v3` (George), generated by `../el.py say` with
`--seed 7` so the take is reproducible. **`eleven_v3` ignores the `speed`
parameter** — length is controlled by cutting words, at a measured ~2.2 words/
second. The music bed is `/v1/music`; the send-click is `/v1/sound-generation`.
ffmpeg pre-mixes VO + bed (−18 dB, faded) + click into one deterministic
`assets/track.mp3`, so the render carries a single audio stream.

The word-timings JSON (`../out/vo/demo-28s.words.json`) is what every reveal is
timed against — each `tl.to(...)` offset in `index.html` is a word's start time.
Re-record the VO and the annotation timings move with it.

**Crop-zoom math.** Each `.layer` is `transform-origin: 0 0` with
`translate(x,y) scale(s)`, so the visible region is `[-x/s, -x/s + 1920/s]`. To
never expose blank canvas, `x` and `y` are clamped to `[frame − frame·s, 0]`;
every keyframe pair interpolates *along* that clamp so no intermediate frame
opens a gap. Annotation underlines live inside the same layer, positioned in
image pixels, so they magnify with the text they point at.

## Rebuild

```bash
npm run check     # lint + runtime + layout + motion + contrast — must be 0 errors
npm run render
# then normalise for the web (the raw render lands ~-17.4 LUFS):
ffmpeg -i renders/<raw>.mp4 -c:v copy -af "loudnorm=I=-14:TP=-1.5:LRA=7" \
       -c:a aac -b:a 192k -movflags +faststart renders/charto-demo-30s.mp4
```

To re-capture the stills: start `charto/data/restart.sh` (dataserver, `:5174`)
and `charto/preview/serve.py` (`:5173`), then drive the UI with Playwright at a
1920×1080 viewport. The chat panel is set to **440px** via
`localStorage.charto_chat_width` — the default 44% leaves too little chart for
a wide frame.

## Known trade-offs

- The S1 push is **top-anchored** so it never crops the toolbar wordmark; the
  cost is that it eats empty volume-pane space at the bottom instead.
- The film is silent on F&O, screening, backtests, and position planning. At 30s
  two capabilities is the honest ceiling — a third would make all three shallow.
  Those belong in the 9:16 feature shorts (`../PLAN.md` §4.2).
