Tier-B: the workaround stack for news sources that won't push to you

The problem in one sentence. Indian financial publishers and regulators (RBI, SEBI, NSE, BSE, BS, ET, Mint, Moneycontrol) don't offer any first-party way to push news at us when something happens — no WebSub hubs, no webhooks, no public WebSocket. So we have to build push semantics on top of what they do offer (RSS feeds, plain web pages, JSON endpoints). Tier-B is the three-container open-source stack that does that.

Before we get to the three components, two foundational ideas need to be crisp: polling vs push, and webhooks.

Foundational concept #1 — polling vs push

Imagine you want to know when a friend posts a new photo. You have two strategies:

  • Polling — every few minutes you open their profile and check. Most of the time there's no new photo, so you've wasted the trip; when there is one, you've missed it for up to that polling interval (say 5 minutes).
  • Push — your friend sends you a text the moment they post. Zero wasted checks; delay measured in seconds.

Push is strictly better when the publisher supports it, but it requires the publisher to have a list of subscribers and to do the work of notifying them. Most websites historically only offered polling — they publish an RSS feed at a known URL, and any reader can come fetch it on whatever schedule they like. The publisher does no work per-subscriber.

Today, Pivot polls 5 RSS feeds on its own (RBI ×3, BBC, Google News) using APScheduler. Each feed is checked every 3–10 minutes. That works but means a news item can sit unread on rbi.org.in for up to 5 minutes before our funnel sees it. We want to shrink that to "seconds after publish".

Foundational concept #2 — what a webhook is

A webhook is the push primitive of the open web. It's just a regular HTTP POST request that some other system sends to a URL we own, the moment something happens. So instead of: 

# Polling: we ask, repeatedly, "anything new?"
while true:
    items = http.get("https://www.rbi.org.in/pressreleases_rss.xml")
    process(items)
    sleep(300)

…we expose an endpoint on our own server:

@app.post("/ingest/news")
def ingest(payload: NewsItem, request: Request):
    # Some other system calls this whenever a new item appears.
    # We do nothing between calls; latency is one network hop.
    process(payload)

And configure the source (or a proxy in front of the source) to POST to that URL whenever there's news. Webhooks are how every modern push integration works — Stripe payments, GitHub commits, Slack messages. Our job in Tier-B is to put webhook-emitting proxies in front of sources that don't emit webhooks themselves.

The Tier-B architecture, at a glance

┌──────────────────────────┐ │ │ Sources WITH RSS ─────► Miniflux ──► POST /ingest/news ─► │ (RBI, BBC, │ Google News) │ │ Sources WITHOUT RSS ───► RSSHub ──► (synthetic RSS) ──► ▲ │ Pivot (Moneycontrol, ET, (feed │ │ news_events LiveMint, NSE factory) │ │ funnel notices) └──────► Miniflux ────────────┘ │ (Stages 1-7) │ Sources with NEITHER ──► changedetection.io ─► webhook ─► │ RSS NOR a public (Playwright + diff) │ feed (SEBI orders, │ NSE corp-filings JSON, │ BSE filings) │ └──────────────────────────┘

Three containers (Miniflux, RSSHub, changedetection.io) live alongside the Pivot backend. They turn every source — regardless of how cooperative it is — into a stream of HTTP POSTs into a single /ingest/news endpoint. Downstream of that endpoint, our existing Phase-1-through-Phase-5 funnel doesn't change at all.

Component 1 · Miniflux

RSS → webhook Apache-2.0 ~30 MB RAM

What it is

Miniflux is a minimalist RSS reader. Same family as Feedly or Inoreader, but a single Go binary you self-host. You give it a list of feed URLs and it polls them on a schedule. Crucially for us, since version 2.0.48 it has a native outbound webhook: every new entry it discovers is POSTed to a URL we configure, signed with an HMAC-SHA256 signature in the HTTP header.

Why we use it

Today we do exactly the same job ourselves inside backend/news_events/workers/poller.py + pipeline/ingest.py. Miniflux is more battle-tested, has its own admin UI for adding/pausing feeds, supports conditional GETs (only re-downloads if the feed actually changed — saves bandwidth), retries failed fetches with exponential backoff, and signs its webhooks. We delete ~200 lines of our own polling code and inherit all of that for free.

How the integration works

# 1. Miniflux is configured (via env or its UI) with:
WEBHOOK_URL    = "https://pivot.app/api/news-events/ingest"
WEBHOOK_SECRET = "$(openssl rand -hex 32)"
FEEDS          = [
    "https://www.rbi.org.in/pressreleases_rss.xml",
    "https://feeds.bbci.co.uk/news/world/rss.xml",
    # ...etc
]

# 2. When Miniflux discovers a new entry, it POSTs this to us:
POST /api/news-events/ingest HTTP/1.1
X-Miniflux-Signature: sha256=9c8a4f...     # HMAC of body, signed with the secret
X-Miniflux-Event-Type: new_entries
Content-Type: application/json

{
  "event_type": "new_entries",
  "feed": { "id": 17, "title": "RBI Press Releases" },
  "entries": [
    {
      "title": "RBI cuts repo rate by 25 bps",
      "url": "https://rbi.org.in/Scripts/BS_PressreleaseDisplay.aspx?prid=63110",
      "published_at": "2026-05-21T04:00:00Z",
      "content": "The Monetary Policy Committee..."
    }
  ]
}

Our endpoint verifies the HMAC (so we know the POST is from our Miniflux, not a random attacker spamming us with fake news), then writes the entries into the existing news_articles table — exactly the same schema Stage 1 + Stage 2 already operate on. From there, the funnel is unchanged.

Trade-offs to be honest about

  • Still polling under the hood. Miniflux itself polls the publisher; the "push" is from Miniflux to us. That pushes latency from "our 5-minute APScheduler tick" down to "Miniflux's 1-minute tick + zero queue delay" — roughly 5×–10× faster but not literally sub-second.
  • Single point of failure. If our Miniflux container crashes, polling stops. APScheduler-in-process has slightly better recovery semantics because it shares a process with the backend. Mitigation: a 60-second health check that page-failover-restarts.

Component 2 · RSSHub

non-RSS site → RSS MIT ~200 MB RAM

What it is

RSSHub is a feed factory. It's a Node.js server with 1,300+ community-contributed "routes" — each route knows how to scrape one specific website and generate a synthetic RSS feed from it. Moneycontrol, Economic Times, LiveMint, NSE notices, BSE corporate actions all have community routes. So even though Moneycontrol's homepage doesn't have an RSS feed, RSSHub can produce one for us at e.g. https://rsshub.local/moneycontrol/news/business and Miniflux treats it like any other feed.

Why this matters

Phase-1 verification showed that BS / ET / Mint return HTTP 403 to a generic Python user-agent. Their public RSS endpoints exist but are fragile; RSSHub instead scrapes the actual HTML pages with a browser-like header set, parses the article cards out of the DOM, and emits a clean feed. It also creates feeds for sources that have none — for instance, NSE's "Latest Notices" page is plain HTML with no RSS, but the RSSHub route /nseindia/notices turns it into one.

The pattern

# Without RSSHub:
Miniflux ──► ✗ no feed exists on Moneycontrol ──► we have to skip Moneycontrol entirely

# With RSSHub:
Miniflux ──► GET http://rsshub:1200/moneycontrol/news/business
              │
              ▼
           RSSHub scrapes moneycontrol.com, parses,
           returns a valid <rss> document
              │
              ▼
           Miniflux parses it like any other feed → webhook to us

The escape hatch when a route is missing

If a publisher we want isn't covered by a community route (rare for the major Indian sources), we write a route in ~50 lines of TypeScript and PR it upstream. The route is a function that fetches the source URL, walks its DOM with CSS selectors, and returns an array of articles. Cheap to write, cheap to maintain, the next person who needs the same source just benefits.

What it doesn't help with

Sites that hide content behind a login wall (Bloomberg Terminal, paid Bloomberg Quint) or aggressive bot-detection that requires a real browser (NSE's /api/corporate-announcements JSON endpoint, which requires a warmed cookie session). For those, Component 3 is the answer.

Component 3 · changedetection.io

JS-heavy page → webhook Apache-2.0 ~600 MB RAM (with Playwright)

What it is

changedetection.io watches arbitrary web pages and emits a webhook when the rendered content changes. The killer feature is that it can optionally use Playwright — a tool that drives a real headless Chrome browser — so it can read sites that need JavaScript to render content, accept cookies, and bypass simple bot detection.

JS-heavy page · headless Chrome · ASP.NET / .aspx page

Why we need it for SEBI and NSE corporate filings

SEBI's orders page lives at www.sebi.gov.in/.../orders.html — pure ASP.NET, no RSS, no JSON API. NSE's corporate-announcements feed at www.nseindia.com/api/corporate-announcements is JSON but requires a real browser session (warm cookies + realistic user-agent + referrer) or you get a 401. RSSHub doesn't have a working route for either as of May 2026 — the standard HTTP-with-browser-UA tricks fail.

changedetection.io's approach: spin up Playwright, navigate to the page, wait for the JavaScript to finish, take the rendered text, hash it with SHA-256, compare to the previous hash. If different, POST the new content (or a structured diff) to a webhook.

The pattern

# changedetection.io config (one entry per page we want to watch):
[
  {
    "url": "https://www.sebi.gov.in/sebiweb/.../orders.html",
    "check_interval": "5m",
    "fetch_method": "playwright",    # use real Chrome
    "include_filters": [".orders-table tr"],  # CSS selector — only watch the orders table, not the nav
    "notification_url": "https://pivot.app/api/news-events/ingest"
  }
]

# When the orders table changes, changedetection.io POSTs:
{
  "source": "sebi_orders",
  "url": "https://www.sebi.gov.in/.../orders.html",
  "diff": "+ New order against XYZ Ltd dated 2026-05-21\n- (no change above)",
  "current_content": "...rendered page text..."
}

Why "diff" matters

A page can change in tiny irrelevant ways every minute — a "last updated" timestamp in the footer, a rotating banner ad, a visit-counter widget. If we treated any change as news, we'd flood the funnel. CSS-selector filters (include_filters) plus diff-aware notification means changedetection.io only POSTs us when the part of the page we care about changes, and tells us what specifically changed.

Operational caveats

  • Playwright is heavy. Each watched page consumes ~150 MB of Chrome memory while it renders. Realistic budget: 20-30 watched pages on a 4 GB host, comfortably.
  • The publisher can change the page layout. If SEBI reskins their site, our .orders-table tr selector breaks and we silently stop receiving updates. Mitigation: a canary check that confirms we received at least one change per source per week.

How Tier-B plugs into the Pivot funnel

The Phase-0 plan deliberately built the funnel around a SourceAdapter abstraction: 

# backend/news_events/sources/base.py
class SourceAdapter(ABC):
    async def fetch(self) -> list[FetchedItem]:
        ...

Today every adapter is a pull adapter — it implements fetch() and the poller calls it on a schedule. For Tier-B, we add a parallel surface: a webhook receiver that takes the POST from Miniflux / changedetection.io and produces the same FetchedItem records the funnel already knows how to handle. The funnel itself (Stages 1-7, the aggregator, the firing path) doesn't change. That's the whole bet from the Phase-0 design: transport is pluggable; funnel is invariant.

Step-by-step request flow once Tier-B is live

  1. RBI publishes a press release at 10:00:00 IST.
  2. Miniflux's poller hits pressreleases_rss.xml at 10:00:08, sees a new entry, and within ~200 ms POSTs to our /api/news-events/ingest endpoint with the HMAC-signed payload.
  3. Our endpoint verifies the signature, runs the existing Stage-0 dedup (url_hash UNIQUE check), inserts a news_articles row, runs Stage 1 (cross-source title dedup) and Stage 2 (per-spec keyword filter) inline.
  4. The next funnel-worker tick (within 60 s) picks up the resulting classification row, fetches the body via Stage 3, runs Stage 4 embedding, Stage 5 excerpt, Stage 6 classifier.
  5. Stage 7 aggregator evaluates the spec. If the per-tier firing rule is satisfied, Stage 8 writes a news_fired_events audit row and calls the Touch-1 seam to kick off the user's workflow.

End-to-end latency goes from "up to 5 minutes (current APScheduler tick) + up to 60 s funnel-worker tick" today to "~10 seconds publisher-to-DB" with Tier-B in place. The funnel-worker tick is still the dominant cost on the back end; if we ever needed to shrink that, we'd evaluate the classification inline on the POST (which is fine because Stages 1-2 are microseconds).

What we deliberately are NOT building

  • Our own WebSub hub. WebSub is the open-standard pub/sub for the web (think "RSS but with push"). Running a hub buys nothing because none of our Indian publishers advertise a hub URL. If you're not on the publisher's hub-advertised subscriber list, a hub of your own subscribes to nobody.
  • A heavy message bus (Kafka, RabbitMQ, NATS). Postgres plus FastAPI background tasks handles 5–50 feeds × per-minute cadence with comfortable headroom. Bus comes in only when we have multiple downstream consumers fighting over the same event stream — that's a Phase 8 problem at the earliest.
  • n8n / Huginn / Airflow / Windmill. Those are workflow tools. We don't have multi-step orchestration needs in the transport layer; we have "X → webhook" needs. Right tool for the right job.

Glossary — every technical term used in this page

Apache-2.0 / MIT
Permissive open-source licences. They let us run the software, modify it, and use it commercially without paying or releasing our own code. The "no licence trap" bit matters because some "free" software (AGPL, n8n's Sustainable Use License) carries restrictions that could affect a paid product.
APScheduler
"Advanced Python Scheduler" — a Python library that runs scheduled functions inside your own process. Pivot uses it to fire jobs at fixed intervals (poll RSS every 5 min, run funnel every 60 s, etc.). The Python-process equivalent of cron.
ASP.NET / .aspx
Microsoft's web framework. Pages built with it tend to use server-side rendering with hidden form state ("ViewState") and postback URLs that look like ?prid=63110. They're more painful than plain HTML to scrape because navigating between pages often requires submitting forms rather than following links.
Atom (feed)
The other XML feed format you'll see, alongside RSS. Same job, slightly different tags. Parsers handle both.
Bot detection
Code on the publisher's server that tries to identify and block automated clients (scrapers) versus real human browsers. Common signals: missing browser headers, no cookie session, no JavaScript execution, suspicious request rates. Bypass it by looking and acting more like a real browser — which is exactly what Playwright does.
CSS selector
A short string like .orders-table tr that picks elements out of an HTML page. Same syntax web designers use to style pages. We use them to tell changedetection.io "only watch THIS part of the page".
DOM (Document Object Model)
The in-memory tree representation of an HTML page. When a browser loads a page, it builds a DOM and that's what JavaScript / scrapers manipulate. "Walking the DOM with selectors" means finding the elements we care about within that tree.
Docker / Docker Compose
Docker is a way to package an application together with everything it needs to run, into a "container". Docker Compose is a tool to declare a set of related containers in one YAML file and start them together. Tier-B is three Docker containers + their config — that's the entire ops footprint.
FetchedItem
The internal Pivot dataclass that represents one news article candidate inside our funnel. source_id, url, title, summary, published_at, raw_metadata. Whatever adapter produces it, downstream stages don't care.
Go binary
Programs written in the Go language compile to a single executable file that has no external runtime dependencies. So "Miniflux is a 30 MB Go binary" means we copy one file onto a server and run it — no Python install, no virtualenv, no npm. Operationally cheap.
Headless browser
A real web browser (Chrome, Firefox) running without a graphical window. It still does the full JavaScript execution and rendering work, just doesn't draw to a screen. Used by scrapers when a page won't reveal its content unless JS runs.
HMAC (Hash-based Message Authentication Code)
A cryptographic signature scheme. The sender and receiver share a secret. The sender computes a hash of (the message + the secret) and includes it in the request. The receiver re-computes the same hash with their copy of the secret; if it matches, the message is authentic AND wasn't tampered with. Standard way to prove a webhook POST really came from who it claims to be from.
HTTP POST
An HTTP request that sends data to a URL. Distinct from GET, which only asks for data. A webhook is always a POST — the sender is delivering something to us, not asking for something.
HTTPS / TLS
HTTPS is HTTP over TLS (Transport Layer Security). It encrypts the connection so nobody on the network can read or alter requests in transit. All Pivot webhook endpoints will be HTTPS-only.
Idempotent
"Doing it twice has the same effect as doing it once." Our ingest endpoint is idempotent: if Miniflux retries a POST after a network blip, we don't end up with two copies of the same article — the second insert hits the UNIQUE url_hash constraint and is silently absorbed.
Jinja2
A Python templating language (used here by changedetection.io). Lets you write reusable HTML/text templates with placeholders like {{ current_content }} that get filled in at send time. We mention it because changedetection.io uses it to let you customise the JSON shape of the webhook payload.
Miniflux's "conditional GET"
An HTTP optimisation: when re-fetching a feed, send the If-Modified-Since or If-None-Match header carrying the last response's timestamp / ETag. If the publisher's feed hasn't changed, the server returns 304 Not Modified with no body — saves bandwidth and CPU on both sides.
Playwright
An open-source library (originally from Microsoft) that drives real browsers (Chrome, Firefox, Safari) under programmatic control. Used here by changedetection.io to load JS-heavy pages exactly the way a human browser would, then read the rendered content.
Poller / polling
A loop that wakes up at fixed intervals, asks "anything new?", and goes back to sleep. The opposite of push.
Postback URL
An ASP.NET concept — links on the page don't navigate by themselves; clicking them submits a hidden form that tells the server to re-render. Annoying for scrapers because simple "fetch this URL" code misses the form-submission step.
Pull adapter vs Push receiver
Pivot terminology. A pull adapter implements async fetch() and the poller calls it on a schedule. A push receiver is an HTTP endpoint that accepts inbound POSTs from a webhook and emits the same FetchedItem records. The funnel doesn't care which produced its input.
RSS (Really Simple Syndication)
An XML format publishers expose at a known URL (e.g. /rss.xml) listing their recent items. Readers fetch the URL on a polling schedule. No subscriber list maintained by the publisher; cheap to host, cheap to consume, but inherently polling.
SHA-256
A cryptographic hash function. Takes any input, produces a fixed-length 256-bit digest. Two identical inputs give identical hashes; a single-byte change produces a wildly different hash. Used here as a content fingerprint: hash the rendered page text, compare to the previous hash, alert on mismatch.
Source adapter (Pivot's SourceAdapter abstract class)
The Phase-0 abstraction that lets every funnel-downstream stage be agnostic about where articles came from. The interface is one async method that yields FetchedItem records. Pull adapters implement it directly; push receivers translate inbound webhooks into the same shape.
UNIQUE constraint
A database rule that prevents two rows from having the same value in a given column. Pivot's news_articles.url_hash has one, so an attempted second insert of the same URL fails — that's how Stage-0 dedup is enforced at the storage layer.
User-Agent
The HTTP header a client sends to identify itself. Browsers send things like Mozilla/5.0 ... Chrome/127. Generic Python libraries send python-requests/2.31 which many publishers blocklist. Pivot's polite-citizen rule is to send PivotNewsBot/0.1 (...) so the publisher can identify us and rate-limit us cleanly.
Webhook
An inbound HTTP POST that another system sends to a URL we own, the moment something happens. The "we expose an endpoint and they call it" inverse of polling.
WebSub (formerly PubSubHubbub)
An open standard for push: publishers advertise a "hub" URL in their feed; subscribers register with the hub once; the publisher tells the hub when something changes; the hub forwards to every subscriber. Great when supported. Almost nobody we want supports it in 2026, so we don't use it.
